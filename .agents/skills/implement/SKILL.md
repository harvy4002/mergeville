# Implement Skill

Use this skill to systematically translate a generated specification or implementation proposal into working code.

## Workflow

### Phase 1: Context & Spec Retrieval
1. **Locate Proposal & Tasks**:
   - Check `.memory/specs/{feature-name}/` (where `{feature-name}` is kebab-cased) for implementation artifacts.
   - Read `.memory/specs/{feature-name}/proposal.md`, `.memory/specs/{feature-name}/intent.md`, `.memory/specs/{feature-name}/spec.md` (if applicable), `.memory/specs/{feature-name}/test-cases.md` (if applicable), and the relevant `.memory/specs/{feature-name}/tasks.md` checklist.
   - **Strict Adherence**: The `intent.md` document defines the rigid boundaries, technical constraints, and validation rules for the task. You MUST prioritize these over all other instructions.
   - Locate any UI design artifacts or visual specifications (e.g., `.memory/specs/{feature-name}/design-plan.md`) generated by the `propose` or `ui-mockup` skills.

2. **Review Alignment**: Ensure you have ingested `.memory/architecture.md`, `.memory/design-guidelines.md`, and `.memory/testing.md` to confirm the code generation respects established project and testing constraints.

### Phase 2: Systematic Implementation
Iterate through the tasks identified in the `.memory/specs/{feature-name}/tasks.md` checklist or the Fallback Proposal task list:
1. **Analyze Task**: Understand the exact requirements of the individual step within the broader context of the proposal and the rigid constraints defined in `intent.md`.
2. **Code Generation**:
   - Create or modify the necessary files.
   - Adhere strictly to the workspace conventions, architectural layers, and component patterns identified in the planning phase.
   - **Intent Alignment**: Constantly evaluate the generated code against the `Boundaries & Scope Constraints` and `Technical Constraints` defined in `intent.md`. Do not drift from the specified objective.
   - **Faithful UI Alignment**: Ensure the generated code strictly matches the layout, visual structure, and styling defined in the discovered UI mockups, Storybook, or design specifications.
   - **Strict UI Scope**: You MUST NOT implement, scaffold, or generate any screens, pages, or major views that are not explicitly defined in the design plan, mockups, or task checklist. If a required screen is missing from the spec, halt and request clarification rather than inventing it.
   - **Test Implementation**: You MUST explicitly create and implement the unit, integration, and e2e tests corresponding to the scenarios defined in `.memory/specs/{feature-name}/test-cases.md` by invoking the **`write-tests` skill**. Provide the skill with `.memory/testing.md` and `test-cases.md` to ensure correct output. Ensure that both the feature code and the newly created tests fully satisfy these testing scenarios.
3. **Continuous Tracking**:
   - If technical hurdles emerge requiring a new architectural choice, halt and use the **`adr` skill**.
   - If missing details require an educated guess, use the **`save-assumption` skill** to document it.
   - If implementation validates or invalidates an existing assumption, use the **`save-assumption` skill** to update its status.

### Phase 3: Task Tracking & Completion
As each task is successfully implemented and locally verified:
1. **Update Task Checklist**: Mark the corresponding task as complete (`[x]`).
   - Update `.memory/specs/{feature-name}/tasks.md` directly in accordance with the structured specification conventions.
2. **Verification**: Ensure the generated code is syntactically correct, matches the spec, and that all required tests defined in `test-cases.md` have been implemented and are passing before moving to the next task.

### Phase 4: Final Validation
Once all tasks are completed:
1. **Comprehensive Test Execution**: Ensure all tests—including unit, functional, integration, security, and end-to-end tests—compile and run.
2. **Verify Results**: Confirm that every test passes successfully.
3. **Intent Validation**: Perform a mandatory cross-reference of the completed implementation against the `Measurable Success Criteria` and `Validation Rules` in `intent.md`.
4. **Strict Adherence**: Do NOT ignore or skip any tests or validation rules. All tests must be passing and all criteria in `intent.md` must be satisfied to consider the implementation complete.
